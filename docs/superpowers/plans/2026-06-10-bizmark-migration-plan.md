# Bizmark.ID — Site Migration Plan: `/new` → `https://bizmark.id/`

> **Prepared:** 2026-06-10
> **Server:** Nginx reverse proxy → PHP 8.4 FPM
> **Framework:** Laravel 12
> **Root:** `/home/bizmark/bizmark.id/public`
> **Nginx config:** `/etc/nginx/sites-enabled/bizmark`

---

## 1. Strategy Overview

**Approach:** Laravel route-level swap — change the root `/` route to serve new views, then add 301 redirects for old URL patterns that differ from new ones. This avoids touching Nginx configs for the core swap and keeps all redirect logic in the application layer.

| Phase | Action | Impact |
|-------|--------|--------|
| Pre-Launch | Build & test new assets, audit all `/new/` paths | Zero |
| Launch Step 1 | Swap route: point `/` to new landing + redirect `new.*` routes to root | ~1 min traffic overlap |
| Launch Step 2 | Add 301 redirects for removed/modified old paths | Zero after deploy |
| Post-Launch | Verify all routes, monitor 404s, update sitemap | Monitoring |

## 3. Migration Steps (Execution Order)

### Step 1: Update Internal Links in New Templates

Replace all `/new/` prefixed links in `resources/views/new/` with root-relative paths:

| Current Path | New Path |
|-------------|----------|
| `/new` | `/` |
| `/new/layanan` | `/layanan` |
| `/new/proses` | `/proses` |
| `/new/harga` | `/harga` |
| `/new/tentang` | `/tentang` |
| `/new/blog` | `/blog` |
| `/new/kontak` | `/kontak` |

Use this sed command:

```bash
# Replace /new/ with / in href attributes (but NOT in external links)
sed -i 's|href="/new/|href="/|g' resources/views/new/partials/navbar.blade.php
sed -i 's|href="/new"|href="/"|g' resources/views/new/partials/navbar.blade.php
sed -i 's|href="/new/|href="/|g' resources/views/new/partials/footer.blade.php
sed -i 's|href="/new"|href="/"|g' resources/views/new/partials/footer.blade.php
```

### Step 2: Add Open Graph + JSON-LD to New Layout

Add to `resources/views/new/partials/head.blade.php`:

```blade
{{-- Open Graph --}}
<meta property="og:type" content="website">
<meta property="og:url" content="{{ URL::current() }}">
<meta property="og:title" content="@yield('title', 'Bizmark.ID — Perizinan Usaha Indonesia')">
<meta property="og:description" content="@yield('description', 'Platform legal-tech perizinan usaha di Indonesia.')">
<meta property="og:image" content="{{ asset('images/og-image.jpg') }}">

{{-- Twitter --}}
<meta name="twitter:card" content="summary_large_image">
<meta name="twitter:title" content="@yield('title', 'Bizmark.ID — Perizinan Usaha Indonesia')">
<meta name="twitter:description" content="@yield('description', 'Platform legal-tech perizinan usaha di Indonesia.')">

{{-- Canonical --}}
<link rel="canonical" href="{{ URL::current() }}">

{{-- JSON-LD --}}
<script type="application/ld+json">
{
    "@context": "https://schema.org",
    "@type": "WebSite",
    "name": "Bizmark.ID",
    "url": "{{ URL::to('/') }}",
    "description": "Platform legal-tech perizinan usaha di Indonesia."
}
</script>
```

### Step 3: Swap the Root Route

In `routes/web.php`:

1. **Replace** the root `/` route to use `NewLandingController` instead of `PublicArticleController`
2. **Leave** all `/new/` routes temporarily — they continue serving new views during the transition
3. **Add** 301 redirects from old routes to the new controller where paths differ

Old route (remove):
```php
Route::middleware('locale:id')->get('/', function (\Illuminate\Http\Request $request) {
    return app(PublicArticleController::class)->landing($request);
})->name('landing.id');
```

New route (add same position):
```php
Route::middleware('locale:id')->get('/', [App\Http\Controllers\NewLandingController::class, 'home'])->name('new.home');
```

### Step 4: Add 301 Redirects for Old-to-New URL Mapping

Add these redirects after the route swap, before the `/new/` routes:

```php
// 301 Redirects: Old landing routes → new landing routes
// (Only for paths that changed structure — most stay the same)
```

| Old Path | New Path | Redirect? |
|----------|----------|-----------|
| `/` | `/` (same) | No — route swap handles it |
| `/layanan/*` | `/layanan/*` (same) | No — same URL pattern |
| `/proses` | `/proses` (same) | No |
| `/harga` | `/harga` (same) | No |
| `/tentang` | `/tentang` (same) | No |
| `/blog/*` | `/blog/*` (same) | No |
| `/kontak` | `/kontak` (same) | No |

Since the new design uses the **same URL structure**, no path-based 301 redirects are needed. The route controller swap is sufficient.

**Exception:** If any old service pages had different URLs, add explicit 301s:

```php
Route::permanentRedirect('/old-service-path', '/layanan/new-service-path');
```

### Step 5: Remove `/new/` Route Group (or Convert to 301 Redirects)

After confirming the swap works, either:
- **Remove** the `/new/` prefix routes entirely
- **Or** add 301 redirects from `/new/*` → `/*`

Option: Add redirects to `/new/` routes as fallback:

```php
// Phase-out redirects: /new/* → /*
Route::permanentRedirect('/new', '/');
Route::permanentRedirect('/new/layanan', '/layanan');
Route::permanentRedirect('/new/proses', '/proses');
Route::permanentRedirect('/new/harga', '/harga');
Route::permanentRedirect('/new/tentang', '/tentang');
Route::permanentRedirect('/new/blog', '/blog');
Route::permanentRedirect('/new/kontak', '/kontak');
```

### Step 6: Deploy

```bash
cd /home/bizmark/bizmark.id

# 1. Clear caches
php artisan view:clear
php artisan config:clear
php artisan route:clear
php artisan cache:clear

# 2. Rebuild with a fresh production build
npm run build

# 3. Warm caches
php artisan view:cache
php artisan config:cache
php artisan route:cache

# 4. Restart PHP-FPM (if using cache)
sudo systemctl reload php8.4-fpm
```

## 4. Post-Launch Verification

```bash
# Verify all key pages return 200
for path in "/" "/layanan" "/proses" "/harga" "/tentang" "/blog" "/kontak" "/konsultasi-gratis" "/login" "/permohonan"; do
    status=$(curl -s -o /dev/null -w "%{http_code}" https://bizmark.id$path)
    echo "$path → $status"
done
```

Expected: all return `200`.

### 4.2 Redirect Verification

```bash
# Verify /new routes redirect to root
```

## 5. Rollback Plan

If critical issues are found post-launch:

```bash
# 1. Restore old route in routes/web.php
git checkout HEAD~1 -- routes/web.php

# 2. Clear and recache
php artisan route:clear
php artisan route:cache

# 3. Verify old site works
curl https://bizmark.id/

# 4. Investigate and fix before re-deploying
```

**Rollback triggers:**
- 500 errors on the root page
- 404s on critical paths (blog, layanan)
- Missing CSS/JS causing broken layout
- Form submissions failing (konsultasi-gratis, permohonan)

## 6. Risks & Mitigations

| Risk | Likelihood | Impact | Mitigation |
|------|-----------|--------|------------|
| Broken `/new/` links in templates | Medium | High | Pre-launch `grep` audit |
| Missing OG tags hurt social share | Low | Medium | Added in pre-launch checklist |
| Route conflict between old and new | Low | High | Keep routes separate, test thoroughly |
| Vite asset cache stale | Low | Medium | `npm run build` before deploy |
| PHP-FPM cache stale | Low | Low | `systemctl reload php8.4-fpm` |
| Existing users see broken page during deploy | Low | Low | Deploy window < 1 minute |
